■ 情報
========================================================================

------------------------------------------------------------------------
Ｅ-1　Threads API で返信を送るのは「公式に用意された使い方」
------------------------------------------------------------------------
【確定】Threads API には返信を送る・読む・隠す・承認する機能がある
　必要な権限：読む＝threads_read_replies ／ 送る・管理＝threads_manage_replies
　出典: developers.facebook.com/docs/threads/retrieve-and-manage-replies
【定説】公式APIで自分の投稿への返信に答えるボットは認められている。
　パスワードでログインしてアプリを操作するタイプ（フォロー・いいね・DMを自動化）は規約違反で、止められる
　出典: Elev8or「Threads Bot: What Is Safe and What Is Not」ほか

------------------------------------------------------------------------
Ｅ-2　上限（24時間の中で数える。毎日0時に戻るのではなく「直近24時間」）
------------------------------------------------------------------------
【確定】出典: developers.facebook.com/docs/threads/overview
　投稿　250件 ／ 返信　1,000件 ／ 削除　100件 ／ 場所検索　500件
　APIの呼び出し回数：4,800 × 表示回数（表示が少ないと最低10として計算）
　→ 表示が少ないうちは、呼び出せる回数も少ない（4,800×10＝48,000回/日。実用上は足りる）
【確定】残りは GET /{user-id}/threads_publishing_limit で確認できる（reply_quota_usage）

------------------------------------------------------------------------
Ｅ-3　★ DM（メッセージ）は API で送れない
------------------------------------------------------------------------
【確定に近い】Threads のDM機能は 2025-07 に始まったが、DMを送る・読むAPIは無い
　・公式の変更履歴（2024-04〜2026-08）を全部見たが、メッセージ関連の追加は1つも無い
　・2026-04-14 の公式ブログ「Threads API の新機能」にもDMは無い
　・複数の開発者向け記事が「2026年5月時点で無い」と書いている
　→ Instagram で流行っている「コメントした人に自動でDMを送る」型は、Threads では作れない
　→ 自動化できるのは「公開の返信」だけ。LINE への誘いは公開の場でやることになる（→ 05）

------------------------------------------------------------------------
Ｅ-4　自分のアカウントだけなら、Meta の審査は要らない
------------------------------------------------------------------------
【確定】アプリに「役割」を持つ人・テスターとして登録した人は、審査前でも権限を出せる
　他人のアカウントで使わせる時だけ、権限ごとの審査（画面録画の提出、2〜4週間）が要る
　→ 九尾のアカウント1つで使うなら、審査なしで動かせる（今の作りはこれ）

------------------------------------------------------------------------
Ｅ-5　Webhook（返信が来た瞬間に知らせてもらう仕組み）は条件が重い
------------------------------------------------------------------------
【確定】出典: developers.facebook.com/docs/threads/webhooks
　受け取るには
　　・アプリを「ライブモード」にする
　　・アプリにつながった「ビジネス」の認証（Meta のビジネス認証）が必要
　　・審査（App Review）を通っていること
　　・相手が非公開アカウントの場所で起きた返信は通知されない
　→ 個人でやるには重い。今の作り（10分おきに見に行く）で問題ない
　→ 将来「即レス」が大事と分かったら、そこで検討

------------------------------------------------------------------------
Ｅ-6　トークン（鍵）の寿命
------------------------------------------------------------------------
【確定】短いトークン 1時間 ／ 長いトークン 60日
　長いトークンは「発行から24時間以上」「まだ切れていない」なら延長でき、延長した日から60日
　60日間一度も延長しないと、二度と延長できない（取り直し）
　非公開アカウントの場合は90日
【未確認】延長したとき、トークンの文字列そのものが変わるのか同じなのか。
　→ 今のコードは「新しいトークンは Secrets に自動で入らない」と書いてある。
　　文字列が同じなら問題なし、変わるなら60日後に止まる。実物で確かめる必要あり

------------------------------------------------------------------------
Ｅ-7　スパム扱いの基準（Meta 全体のルール。Threads にも適用）
------------------------------------------------------------------------
【確定】Meta コミュニティ規定「スパム」（Facebook・Instagram・Messenger・Threads 共通）
　・「手動でも自動でも、非常に高い頻度で」投稿・シェア・反応・アカウント作成をすること
　・頻度が低くても、同じ内容の繰り返しなど他のスパムの兆候と合わせて制限することがある
　・反応しないと中身を見せない（いいね・シェアしたら見られる、等）は禁止
　・反応と引き換えにプレゼントやお金を出すのも禁止
　・リンク先と説明が違う、見せる先を審査と利用者で変える、なども禁止
　→ Meta は「自動か手動か」より「量と繰り返し」で見ている
　→ 同じ文の返信（定型文）を大量に送るのは危ない。今の fallback_replies（決まった3文）も
　　回数が増えると「繰り返し」に見える可能性がある

【データ（1件の事例）】Meta 開発者フォーラム
　新しいアカウントで画像を1時間に2回APIで投稿 → 2日後に
　「コミュニティを守るため、特定の活動を制限しています」（エラー 2207051）でブロック
　フォロワーの無い新しいアカウント×機械的な頻度、が引き金と見られている
　→ 九尾のアカウントは新しくない。が、返信の頻度を急に上げない方が安全

------------------------------------------------------------------------
Ｅ-8　AIで書いた文に「AIです」と書く必要
------------------------------------------------------------------------
【確定】Meta の「AI情報」ラベルの対象は、本物そっくりの画像・音声・動画が中心。
　文章のアイデア出しや言い回しの手伝いは、表示がなくてもよいと説明されている
【確定】2026-08-07 Meta の開発者向け規約（Meta のAIモデルAPIの規約）に
　「その国の法律が求めるなら、AIで作ったことを利用者に伝えること」が追加。
　※これは Meta のAIを使う場合の規約。九尾は Gemini を使っている
【未調査】日本の法律でAI生成の文章に表示義務があるか → 10_法律 で調べる
　→ 今のところ、AIで書いた返信に表示を付ける Meta 側の義務は見当たらない

------------------------------------------------------------------------
Ｅ-9　API でできるようになったこと（変更履歴から、使えそうなもの）
------------------------------------------------------------------------
【確定】出典: developers.facebook.com/docs/threads/changelog
　2024-08　Webhook／自分の返信を全部取る /me/replies
　2024-10　引用・再投稿／シェア数の取得

　2026-04　Threads 広告まわりが広がる

■ そこからの案（Claude の考え）
========================================================================

　・「コメントにDMで答える」型はできない。誘導は公開返信の中か、プロフィールに頼るしかない
　・Webhook は今は不要。10分おきの見回りで十分（「即レス」の価値が測れてから考える）
　・定型文の使い回しは、スパム判定の「繰り返し」に当たりうる。数を増やすか、毎回少し変える
　・返信の量は上限（1,000/日）よりずっと手前で止める。
　　問題は上限ではなく「機械っぽい頻度・繰り返し」に見えるかどうか
　・トークン延長で文字列が変わるかは、実物で確認が要る（今の作りの穴かもしれない）
　・clicks（リンクのクリック数）が取れるので、LINE への流れは数字で追える
　・「キーワード検索」で、他人の占いの悩み投稿を見つけることは技術的にはできる。
　　ただし他人の投稿への自動返信は、スパム扱いの危険が一番高い使い方（→ 11 反対意見）
