１．なぜ作るのか
========================================================================

　Threadsは「コメントや会話の数」で、投稿が表示される量が変わります。
　つまり、コメントに返事をするほど、その投稿は多くの人に届きます。

　目的は、表示を伸ばして、公式LINEに人を呼ぶことです。
　返信そのもので売るのではありません。そこは勘違いしないこと。

３．どこで動くか
========================================================================

　GitHub Actions の上で、10分おきに動きます。

　　パソコンは関係ありません。閉じていても動きます
　　無料です
　　動いた記録は GitHub の Actions の画面に全部残ります
　　失敗するとGitHubからメールが来ます（＝黙って止まらない）

　前はパソコンの上で動かしていました。それが14日間の停止につながったので、
　今回はパソコンを前提から外しました。


========================================================================
４．どういう順番で動くか
========================================================================

　10分おきに、これを1回やります。

　　1. トークンが生きているか確かめる
　　　　死んでいたら、そこで異常終了して知らせる（黙って続けない）
　　2. 自分の投稿を新しい順に10件とる
　　3. その投稿にぶら下がった会話を全部とる
　　4. 返すべきコメントを選ぶ（5章）
　　5. 返事の文を作る（6章）
　　6. 送る。送ったら15秒あけて次へ
　　7. 1回で12件まで。超えたらそこで終わり。次の10分後に続きをやる


========================================================================
５．誰に返すか・誰に返さないか
========================================================================

　【返す】
　　・自分の投稿に付いたコメント
　　・自分の返信に対する返事（＝会話が続いている相手）

　【返さない】
　　・自分の発言
　　・もう返事をしたコメント
　　・他人どうしの会話（横から入らない）
　　・中身のないコメント（1文字など）
　　・同じ投稿の中で、同じ人に3回返したあと（粘着に見えるため）

　【「もう返したか」をどう知るか】
　　どこにも記録していません。Threadsに聞けば分かるからです。
　　会話の中に、自分の名前で、そのコメント宛ての返信があれば返事済み。

　　記録を持たないので、記録が消えて二重に返す事故が起きません。
　　前の仕組みは返信済みのidをファイルに持っていて、そこが弱点でした。


========================================================================
６．どう返すか（文の作り方）
========================================================================

　AI（Gemini）に、毎回その場で書かせます。決まった文のパターンは持ちません。

　【渡しているもの】
　　・九尾の人となり（config.json の persona）
　　・自分が書いた投稿の本文
　　・その人とのこれまでのやりとり（直近6件）
　　・今回のコメント

　【指示していること】
　　・15〜90文字
　　・話し言葉で自然に。絵文字は0〜1個
　　・相手が書いた言葉をひとつ拾う
　　・聞かれていることには短く答える

　【いちばん大事だと伝えていること】
　　会話が続くように返すこと。こちらで話を畳まないこと。
　　ただし毎回わざとらしく質問を返すのはやめること。
　　「相手がもう一度書きたくなるか」が基準。

　【禁じていること】
　　・断定しない（「必ず」「絶対」）
　　・占いの結果をその場で出さない
　　　　短い言葉では当たらないし、占いが軽く見える
　　・公式LINEや商品の宣伝をしない
　　　　売り込まれたと思われたら、そこで終わりだから
　　・リンクを貼らない
　　・AIが書いたと分かる言い回しをしない


========================================================================
７．宣伝をしない理由
========================================================================

　返信で公式LINEに誘導したくなりますが、やりません。

　理由は2つ。
　　・コメント欄で売り込むアカウントは、見ている人全員に見えている
　　・Threadsは外部リンクを嫌う傾向がある

　導線はプロフィール欄に置きます。
　返信の役目は「この人と話してみたい」と思わせるところまでです。

　※ これは方針なので、変えたくなったらここに書き直してください。


========================================================================
８．危ない話が来たとき
========================================================================

　コメントに次の言葉が入っていたら、AIには書かせません。

　　死にたい／消えたい／自殺／リストカット／殺して

　決まった文で受け止めて、公式LINEかDMに寄せます。
　（文面は config.json の guard.sensitive_reply）

　AIが「必ず」「絶対」「治る」などを書いてしまった場合も、
　その文は捨てて、当たり障りのない決まった文に差し替えます。


========================================================================
９．トークンの寿命（ここが前回の死因）
========================================================================

　Threadsのトークンは60日で切れます。

　【やっていること】
　　・毎回、動く前にトークンが生きているか確かめる
　　・死んでいたら異常終了する → GitHubからメールが来る
　　・1日1回、延命（リフレッシュ）を試みる

　【やっていないこと・注意】
　　延命して新しくなったトークンを、GitHubのSecretsに自動で入れることは
　　していません。手で入れ替える必要があります。

　　ただし、切れたら必ずメールが来るので、
　　前回のように「2週間気づかない」ことは起きません。

10．上限（暴走よけ）
========================================================================

　　1回で見にいく投稿　　　　10件
　　1回で送る返信　　　　　　12件
　　同じ投稿・同じ人への返信　3回まで
　　下書きを作ってから出すまで　10秒あける
　　返信と返信のあいだ　　　　15秒あける
　　深夜1時〜7時　　　　　　 動かない（即レスが続くと人に見えないため）

　全部 config.json で変えられます。


========================================================================
11．動かすのに要るもの
========================================================================

　【GitHubのSecretsに入れるもの】
　　THREADS_ACCESS_TOKEN　… Threadsのアクセストークン
　　GEMINI_API_KEY　　　　 … Geminiのキー（九尾で使っているものと同じでよい）

　【確認のしかた】
　　node scripts/selftest.js　… 通信せずに、判断の部分だけ確かめる
　　node index.js --dry　　　 … 実際に会話を読んで、何を返すつもりか出す。送らない

　　いきなり本番で動かさず、必ず --dry で中身を見てからにしてください。
