========================================================================
０．この調査は何のためか
========================================================================

　自動返信を「どう作るか」を決める前に、
　Threads が「何を見て、誰に、どれだけ表示するか」を、できるだけ確かめておく。

　目的のつながり
　　返信の数・中身 → 表示が増える → 九尾を知る人が増える → 公式LINEに登録

　だから、返信だけでなく
　「表示」「フォロー」「LINEへ流れる」までの全部を調べる。
　返信から少し離れた話でも、このつながりに効くなら調べる。


========================================================================
１．調べ方（情報の確からしさを5段階で分ける）
========================================================================

　Threads の仕組みは細かくは公開されていない。
　なので、見つけた情報には必ず「どれくらい確かか」の札を付ける。
　札のない情報は書かない。

　　【確定】 Meta の公式文書に書いてある
　　　　　　（ヘルプセンター、透明性センター、開発者向け文書、利用規約）
　　【公式発言】 Threads/Instagram の責任者（アダム・モセリ等）や社員の発言
　　　　　　　　※本人のThreads投稿・インタビュー。言い方があいまいなことが多い
　　【データ】 第三者が数字を集めて分析したもの（Buffer など大手の調査）
　　　　　　　※何件で調べたか、いつの調査かも書く
　　【定説】 多くの運用者が同じことを言っているが、根拠は経験
　　【噂】 一部の人が言っているだけ。反対意見があるものも含む

　さらに全部の情報に「いつの情報か」を書く。
　Threads は2023年に始まり、何度も仕組みが変わっている。
　古い話が今も正しいとは限らないので、時期を必ず残す。

　調べる場所
　　・Meta 公式：Threads ヘルプセンター / 透明性センター（AIの仕組みの説明書き）
　　　/ おすすめに出さない内容の基準 / Threads API の文書 / 開発者ポリシー
　　・モセリ氏の発言（Threads 上の投稿、週1の質問回答、インタビュー記事）
　　・海外のSNS分析会社の調査記事（Buffer, Hootsuite, Sprout Social, Metricool 等）
　　・日本の運用者の記事・note・ブログ（日本は Threads の利用が特に多い国）
　　・海外の掲示板（Reddit 等）の体験談 ※【噂】扱い
　　・ニュース（仕組みの変更、BAN・規制の話）

　注意：Claude の知識は2026年6月まで。それ以降の変更は、検索で拾えた分しか分からない。
　　　　拾えなかったことは「分からない」と書く。推測で埋めない。

------------------------------------------------------------------------
Ａ．★ 表示の仕組みの全体像
------------------------------------------------------------------------
　・「おすすめ」と「フォロー中」の2つの画面で、出し方がどう違うか
　・Meta が公開している「Threads のおすすめの仕組み」の説明書き
　　（何を予測して並べているか。例：いいねしそうか、返信しそうか、等）
　・投稿が「誰に」届くか（フォロワー → 似た興味の人 → さらに外、の順なのか）
　・Instagram とのつながりはどこまで影響するか
　・新しいアカウント（フォロワーが少ない）は不利か、逆に試し出しされるか
　・1つの投稿は、どれくらいの時間おすすめに出続けるか
　・トピックタグ（# の代わりの仕組み）・コミュニティ・検索・「今の話題」からの流入

------------------------------------------------------------------------
Ｂ．★ 評価されるシグナル（何が「良い投稿」と見なされるか）
------------------------------------------------------------------------
　・返信、いいね、再投稿、引用、シェア（DMで送る）のうち、何がどれだけ効くか
　・最初の30分〜1時間の反応が大事、という説は本当か
　・読まれた時間（じっくり読まれたか）は見られているか
　・投稿からプロフィールを見に行った、フォローした、は効くか
　・文字数、画像・動画・アンケート・カルーセルの有無で差があるか
　・投稿する時間帯、頻度、毎日続けているか
　・投稿の削除や編集は不利になるか

------------------------------------------------------------------------
Ｃ．★★ 返信そのもの（いちばん厚く調べる）
------------------------------------------------------------------------
　・投稿者本人が返信すると、その投稿の表示は伸びるのか（公式はどう言っているか）
　・返信の「往復」（相手がさらに返してくる）は、1回の返信より強いのか
　・返信はどれくらいの速さですべきか（すぐ返すべきか、間を空けるべきか）
　・返信の長さ、質問で終わる返信は会話を伸ばすか
　・コメント欄の並び順はどう決まるか（どの返信が上に出るか）
　・返信が、フォロワーの画面に「別の投稿」として出ることはあるか
　・他人の投稿に返信しに行くこと（外への返信）で、自分が知られるか
　・コメントにいいねを付けることの効果
　・「コメントしてくれた人を占います」型の投稿は伸びるのか、罰を受けるのか
　　（→ Ｄ の「反応をねだる投稿」の罰と、ぶつかる可能性がある）

------------------------------------------------------------------------
Ｄ．★ 表示されにくくなること（罰・抑制）
------------------------------------------------------------------------
　・Meta が公開している「おすすめに出さない内容」の基準
　　（健康の誇大な話、根拠のない主張、等。占い・スピリチュアルは当たるのか）
　・「いいねして」「コメントして」と反応をねだる投稿への罰
　・他人の投稿の使い回し、オリジナルでない内容への罰
　・同じ文の返信を繰り返す、短時間に大量に返信する、などスパム扱いの条件
　・機械的な動き（自動化）は見抜かれるか、見抜かれたらどうなるか
　・外部リンク（LINEへのリンク）を貼った投稿は表示が減るのか
　・「興味なし」「非表示」「ミュート」「ブロック」「通報」が付くと、どれだけ響くか
　・「アカウントのステータス」画面で何が分かるか。いわゆるシャドウバンは実在するか
　・政治の話はおすすめに出ない初期設定、などのジャンル別の扱い

------------------------------------------------------------------------
Ｅ．★ 自動化のルール（守らないとアカウントごと消える部分）
------------------------------------------------------------------------

　・1日に送れる返信の上限、投稿の上限（API の制限）
　・返信を読むための権限、Meta の審査が要るかどうか
　・トークン（鍵）の有効期限と更新の仕方
　・AIで作った文に「AIです」と書く必要はあるか（Meta の方針）
　・自動化でアカウント停止になった実例

　【2026-10-07 追加：ここは力を入れて調べる（山崎さんの指示）】
　会話の中で、どうやって LINE につなげるのがいいか。そもそも、それはありなのか。

　＜ありなのか（やっていいのか）＞
　・Threads/Meta の規約で、返信やDMから外のサービス（LINE）に誘うのはどう扱われるか
　・LINE 公式アカウント側の規約で、外からの誘い方に決まりはあるか
　・利用者の目から見て「売り込み」と感じて離れる境目はどこか
　・同じ文の誘いを何人にも送ると、スパム扱いになるか

　＜できるのか（仕組みとして）＞
　・Threads の DM（メッセージ）は API で送れるのか。送れるなら条件は
　　（Instagram で流行っている「コメントした人に自動でDMを送る」型が Threads でできるか）
　・返信にリンクを貼れるか、貼ると表示が落ちるか

　＜どうつなげるのがいいか（うまい人はどうしているか）＞
　・会話の何回目で、どんな言い方で LINE を出しているか

　・「続きは LINE で」「無料で詳しく見ます」など、誘い文句の型と、その効き目
　・返信では一切誘わず、プロフィールと固定投稿に任せる、という考え方の是非
　・占い・相談系で、Threads → LINE の流れをうまく作っている実例
　・LINE に来たあと続く人と、すぐブロックする人の違い（入口の期待とのズレ）

　※ここは「情報」と「どうするかの案」が混ざりやすい。

４．調べた結果の書き方（調査メモ.txt の形）
========================================================================

　結果は別のファイル「調査メモ.txt」に書く。形はこう：

　　・項目ごと（Ａ〜Ｌ）に分ける
　　・1つの情報 ＝ 1行の要約 ＋ 札（確定/公式発言/データ/定説/噂）＋ 時期 ＋ 出典
　　・同じことで意見が割れていたら、両方書く
　　・最後に「自動返信をどう作るかへの示唆」をまとめる
　　　→ ここから先、作るものを決めるのは山崎さんと相談して

　分量は多くてかまわない（山崎さんの指示）。
　ただし、いちばん上に「まず読むべき10個」を置いて、全部読まなくても要点が分かるようにする。

５．このあとの流れ
========================================================================

　１．この調査計画を山崎さんが見て、直す（2026-10-07 OK）
　２．OKが出たら、本番の調査（時間もトークンも惜しまない）（2026-10-07 1回目済み → 調査メモ/ フォルダ）
　３．調査メモを山崎さんが読む ← いまここ（入口は 調査メモ/00_まず読む.txt）
　４．相談して、自動返信で何を作るかを決める
　５．返信システムの仕様書.txt を書き直す
　　　※今ある仕様書は、調査の前に書いたもの。調査の結果で大きく変わってよい
　６．少しずつ作る。いきなり完成を目指さない

　ただし、この順番はきっちり分かれたものではない（山崎さんの考え 2026-10-07）
　　・「情報 → 計画 → 実装」の3段階は、重なったり行き来したりする
　　・調査の中に、どうするかの案が混ざるのは仕方ない。
　　　ただし調査メモでは「情報」と「そこからの案」は分けて書く
　　・計画と実装はほぼ同時に進む。作りながら調べることもある
　　・計画の段階にはかなり時間をかける。メモを作っては、また新しく作り直す
　　・いきなり完璧を目指さない。手違いを防ぎ、途中のいい発見を見落とさないため
　　・調べる範囲は自動返信に限らない。
　　　遠い情報からも逆算できるし、自動返信以外の Threads 占いの活動にも使える

　メモの決まり（山崎さんの指示 2026-10-07）
　　・作るもの・変えることは、必ずメモにも書く。メモにないことはしない
　　・山崎さんが「メモをゼロから作り直して」と言ったら、
　　　今までのメモを直すのではなく、それまでの構想を元に白紙から書き直す
　　　（最初に決まった形に縛られないため）
　　・その指示がない間は、Claude がメモを自由に更新してよい
